The LLM wiki pattern is a persistent, compounding knowledge layer
between an LLM agent and its raw sources. It is a substrate for
long-term memory, not a knowledge base in the traditional sense —
the agent is the curator, the wiki is the durable artefact.

Three components, all plain text. **Raw sources** are immutable;
they are the ground truth the agent cites. **Wiki pages** are
markdown with YAML frontmatter; the agent writes them as
synthesised, compressed claims rather than transcripts.
**Index** and **log** are auto-generated: the index is a
human-readable catalog grouped by page type, the log is an
append-only event stream that records every mutation.

## Key points

- The agent does the "smart" work; the substrate is dumb
  storage and search.
- Sources are never edited. If a source turns out to be wrong,
  write a new source or annotate the conflict in the page that
  cites it.
- A page is a compressed claim with a citation, not a
  transcript. Synthesis, not copy-paste.
- The index lets a fresh agent orient itself without reading
  every page. The log lets a future agent audit how knowledge
  evolved.
- Discipline — schema discipline — is what keeps the wiki from
  rotting into a heap of transcripts.

## Open questions

- How does the pattern degrade when an agent hallucinates a
  source id? (The linter catches missing sources, but not
  sources that exist and are miscited.) — follow-up idea:
  require the agent to include a one-line excerpt from the
  source in the page, hash-matched at write time.
- Should the index be regenerated lazily or eagerly? Eager
  keeps it consistent; lazy is cheaper at scale. mnemos
  currently regenerates eagerly on every page write.
